# AI 一键商品主图 PRD

Nov 2, 2026 · @Roy

## 1. 背景与问题

卖家在发布页上传随手拍的实物照片，点一下就能得到一张背景干净、主体居中、光线均匀的主图，同时不改变商品的真实外观和成色。

二手卖家多是个人，用手机在家里拍照，主图常见四类问题：

- **背景杂乱**：床单、桌面杂物、宠物、快递盒入镜，抢走主体。
- **光线与色彩差**：室内偏暗、偏黄，商品颜色失真。
- **构图失衡**：主体太小、歪斜、被裁掉一角。
- **修图门槛高**：抠图、调光要切到第三方 App，多数卖家会直接放弃。

主图是买家在信息流和搜索结果里决定是否点进详情的第一依据，主图质量差会直接拉低曝光转化和成交。

二手场景和新品电商有一个本质区别：买家要看的是**这一件**商品的真实状况。过度美化会造成“货不对板”纠纷，所以本功能的定位是“整理画面”，不是“美化商品”，第 7 节把这条写成硬约束。

## 2. 目标与成功指标

本期要证明一件事：用 AI 主图的商品点击和成交更好，而货不对板纠纷不增加。下表目标值为建议值，需在埋点拿到基线后校准。

| 类型 | 指标 | 定义 | 建议目标 |
| --- | --- | --- | --- |
| 北极星 | 14 日成交率 | 发布后 14 天内成交的商品数 / 发布商品数（实验组 vs 对照组） | 相对提升 ≥ 5% |
| 核心 | 主图点击率 | 列表页主图曝光→进入详情的比例 | 相对提升 ≥ 10% |
| 采用 | 使用率 | 新发布商品中点击过“AI 一键主图”的比例 | 上线首月 ≥ 30% |
| 采用 | 采纳率 | 生成后最终设为主图并发布的比例 | ≥ 60% |
| 护栏 | 货不对板纠纷率 | 成交订单中因“描述或图片与实物不符”发起的售后比例 | 不显著高于对照组 |
| 护栏 | 发布耗时 | 进入发布页到提交的时长中位数 | 增加 ≤ 15 秒 |
| 护栏 | 生成失败率 | 无可用候选图的请求 / 全部请求 | ≤ 5% |

不以“主图好看”的主观评分作为成功标准；人工抽检只用于保真度和质量门槛（见第 7、8 节）。

## 3. 目标用户与核心场景

首要用户是不会修图、也不愿意花时间修图的个人卖家；买家是间接受益方，他们的诉求是“看得清、且看到的是真的”。

| 用户 | 特征 | 核心诉求 | 本期优先级 |
| --- | --- | --- | --- |
| 闲置清理型个人卖家 | 偶尔发布，在家用手机拍，不会抠图 | 少操作、快发布、卖得出去 | P0 |
| 高频小卖家 / 回收商 | 每周发布多件，品类较固定 | 主图风格统一、店铺看起来专业 | P1（批量处理不在本期） |
| 个人二手车卖家 | 户外拍车，背景是停车场或街道 | 车身清晰、角度端正 | P1（仅调光与裁剪） |
| 买家 | 在信息流中快速筛选 | 一眼看懂卖的是什么，成色可信 | 受益方 |

典型场景：

1. 卖家在床上拍了一双球鞋，背景是花床单；一键后得到浅灰背景、鞋子居中的主图，鞋头磨损依然可见。
2. 卖家夜里在台灯下拍耳机，画面偏黄偏暗；一键后白平衡和曝光被校正，颜色接近实物。
3. 卖家一次上传 6 张照片；系统自动挑出主体最清晰的一张做主图，其余照片保持原样作为详情图。
4. 卖家编辑一个已发布但无人问津的商品，用一键主图替换旧主图。

## 4. 范围

本期只做“整理画面”：换背景、调光、裁剪；一切会改变商品本身像素的能力都不做。类目上先覆盖通用实物，房产不接入。

**本期做（MVP）**

- 通用实物类目：主体抠图 + 纯色背景（浅场景背景为 P1） + 自动居中裁剪 + 全局曝光与白平衡校正。
- 多张原图时自动推荐一张作为输入，卖家可改选。
- 一次生成 3 张候选，支持与原图对比、换一批、放弃。
- 保真度自动校验、原图强制保留、“AI 优化”标识。
- 二手车类目（P1）：仅调光与裁剪，不换背景。
- 入口：发布页 + 已发布商品的编辑页。

**本期不做**

- 去除或修补划痕、污渍、磨损、褶皱等任何局部重绘。
- 生成式“补全”商品缺失部分、改变商品颜色或形状。
- 模特上身、虚拟试穿、场景合成人物。
- 文字海报、促销贴纸、价格水印。
- 房产类目（房屋照片抠图无意义，且美化容易构成虚假宣传）。
- 针对高频卖家的批量处理、店铺统一模板。
- 视频主图、详情图的批量美化。

## 6. 功能需求详述

P0 共 12 项，构成可上线的最小闭环；带“建议”的数值需在技术验证后确认。

| 编号 | 功能 | 规则 | 验收标准 | 优先级 |
| --- | --- | --- | --- | --- |
| F1 | 入口与引导 | 发布页上传首张图后，图片区出现“AI 一键主图”按钮；已发布商品的编辑页同样可用；首次使用展示一次气泡引导 | 上传完成后 1 秒内按钮可见；引导每个账号只出现 1 次 | P0 |
| F2 | 输入图推荐 | 多张原图时，按主体清晰度和占比打分，推荐最高分一张；卖家可改选任意一张 | 触发模糊、过暗、过曝、低分辨率的图不被推荐；改选后重新生成 | P0 |
| F3 | 生成前质检 | 输入图质量不达标时提示具体原因（如“画面偏暗，建议靠近窗边重拍”），卖家仍可选择继续生成 | 提示文案与质检标签一一对应；不强制拦截 | P0 |
| F4 | 主体识别与抠图 | 识别商品主体并分离背景；多件套装整体保留；识别不到主体时提示重拍 | 评测集上边缘无明显缺损的比例 ≥ 95%（建议） | P0 |
| F5 | 纯色背景 | 默认纯白、浅灰两种，带轻微接触阴影，避免“漂浮感” | 背景不含任何额外物体 | P0 |
| F6 | 场景背景 | 按类目推荐 4–6 种浅场景（木桌面、浅色布面等）；不得生成与商品相关的配件或道具 | 人工抽检中背景含额外物体的比例为 0 | P1 |
| F7 | 构图与输出 | 主体居中、占画面 60%–80%、不裁切主体；输出 1:1，长边 ≥ 1080 px | 输出尺寸与占比由脚本自动校验 | P0 |
| F8 | 画质校正 | 仅全局调整：曝光、白平衡、对比度、轻度降噪；幅度受第 7 节保真度阈值约束 | 主体区域无局部重绘 | P0 |
| F9 | 候选与换一批 | 每次生成 3 张不同背景的候选；“换一批”每件商品每天 ≤ 5 次（建议） | 超限后按钮置灰并提示原因 | P0 |
| F10 | 与原图对比 | 候选页长按或点击“原图”即可切换查看输入原图 | 切换响应 < 200 ms | P0 |
| F11 | 手动微调裁剪 | 选中候选后可拖动缩放裁剪框 | 微调后仍满足 F7 的尺寸要求 | P1 |
| F12 | 设为主图与原图保留 | AI 图排第 1 张，其源原图自动排第 2 张；AI 主图存在期间源原图不可删除 | 删除源原图时提示并同步撤销 AI 主图 | P0 |
| F13 | AI 标识 | 列表页主图角标“AI 优化”；详情页说明“主图背景经 AI 处理，商品实拍见第 2 张” | 所有 AI 主图均带标识，卖家不可关闭 | P0 |
| F14 | 失败与降级 | 保真度校验不过或抠图失败时，降级为仅调光 + 裁剪并说明原因；全部失败则保持原图 | 任何失败都不阻塞发布 | P0 |
| F15 | 二手车类目 | 只开放调光与裁剪，不换背景 | 车辆类目不出现换背景候选 | P1 |

**与现有平台能力的衔接**

- **图片质量检测**：F2、F3 复用现有的模糊、亮度、分辨率检测（［已删去 capstone 内部细节］）。现有阈值是［已删去 capstone 内部细节］评测值，需用通用实物的真实上传重新校准。
- **重复图片检测**：现行规则对［已删去 capstone 内部细节］的新图直接拒绝。AI 主图与其源原图（尤其降级模式下只调光裁剪）很可能被判为近重复，需按源图 ID 豁免。反过来，换背景后的图会躲开 pHash 比对，所以跨商品盗图检测必须对源原图执行。
- **数据模型**：［已删去 capstone 内部细节］需新增“是否 AI 生成”“源图 ID”“处理类型”等字段，属于 schema 变更，需配套迁移并更新 schema 文档。

## 7. 真实性与合规

硬约束只有一条：AI 可以改背景和画面，不能改商品。以下规则任一不满足，候选图即不展示。

| 规则 | 要求 | 落实方式 |
| --- | --- | --- |
| 主体不重绘 | 主体区域只允许全局色调变换（曝光、白平衡、对比度），不允许生成模型改动主体像素 | 生成模型只作用于背景；主体按掩膜从原图贴回 |
| 颜色保真 | 主体区域与原图的平均色差 ΔE00 ≤ 5（建议） | 生成后自动计算，超阈值降级为仅裁剪 |
| 结构保真 | 主体区域亮度归一化后 SSIM ≥ 0.95（建议） | 同上；阈值在技术验证阶段用评测集校准 |
| 瑕疵可见 | 不去除划痕、污渍、磨损、标签；产品上不提供“去瑕疵”选项 | 由“主体不重绘”保证；上线前人工抽检带瑕疵的样本 |
| 原图强制保留 | 有 AI 主图就必须有对应实拍原图 | 见 F12 |
| 显式标识 | 买家能看出主图经过 AI 处理 | 见 F13 |
| 隐式标识 | 图片文件本身携带 AI 处理标记 | 在元数据中写入标记与处理类型；是否满足上线地区的 AI 生成内容标识法规需法务确认 |
| 内容审核 | 违禁品和敏感图片不进入生成 | 生成前对原图、发布前对 AI 图各走一次现有审核 |
| 防盗图 | 不能让换背景成为绕过重复图检测的手段 | 跨商品重复检测对源原图执行（见第 6 节） |
| 隐私 | 主体上的快递面单、证件、屏幕内容不被放大展示 | 检测到此类信息时提示卖家打码（P1） |
| 数据使用 | 卖家照片不被挨用 | 原图与生成图不用于模型训练，除非卖家单独同意；未采纳的候选图 7 天后删除（建议） |
| 纠纷可追溯 | 客服判责时能看到 AI 处理前后对比 | “图片与实物不符”工单自动附带 AI 标记、源原图和处理参数 |

## 8. 非功能需求

发布流程不能因为这个功能变慢或变脆弱：生成服务全部失败时，卖家仍能用原图正常发布。带“建议”的数值待技术验证确认。

| 维度 | 要求 |
| --- | --- |
| 时延 | 点击到 3 张候选全部可见：P50 ≤ 4 秒、P95 ≤ 8 秒（建议）；候选逐张展示，不等齐 |
| 超时 | 15 秒无结果即按 F14 降级，并允许卖家继续发布 |
| 可用性 | 生成服务月可用性 ≥ 99.5%；不可用时入口置灰并说明原因 |
| 成本 | 单次生成（3 张）的推理成本由技术验证给出，据此确定每日免费次数与“换一批”上限 |
| 容量 | 按“发布峰值 × 使用率 × 人均生成次数”估算峰值请求，并对单用户限流 |
| 输入 | JPEG / PNG / HEIC，单张 ≤ 20 MB；客户端上传前压缩，弱网下可用 |
| 输出 | JPEG，1:1，长边 1080–2048 px，单张 ≤ 1 MB |
| 端覆盖 | Android、Web 体验一致；服务端生成，不依赖端侧算力 |
| 安全 | 生成服务不长期保存原图副本；生成图与商品图片同一对象存储、同一访问权限；第三方模型密钥只从环境变量读取 |
| 可观测 | 按类目监控失败率、降级率、时延分位数；失败率连续 10 分钟 > 10% 告警（建议） |

## 9. 数据埋点与实验方案

按卖家分流做 A/B 实验，按分组（而非“是否使用”）比较结果，至少跑 4 周。下表前 8 行为新增事件；后 3 行是在发布、曝光、售后事件上新增的属性，事件名以现有埋点为准。

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `ai_cover_entry_view` | 入口按钮曝光 | 页面（发布 / 编辑）、类目、已传图片数 |
| `ai_cover_click` | 点击入口 | 输入图是否为系统推荐图 |
| `ai_cover_precheck_warn` | 生成前质检提示 | 质检标签、是否继续生成 |
| `ai_cover_generate_result` | 生成结束 | 成功 / 降级 / 失败、原因、耗时 ms、候选数、ΔE00、SSIM |
| `ai_cover_refresh` | 点击“换一批” | 当天第几次 |
| `ai_cover_compare` | 查看原图对比 | 候选序号 |
| `ai_cover_select` | 设为主图 | 背景类型、是否手动微调 |
| `ai_cover_abandon` | 未选择任何候选即离开 | 停留时长、离开时所在步骤 |
| `listing_publish`（现有） | 发布商品 | 新增 `cover_is_ai`、`cover_edit_type` |
| `listing_impression` / `listing_click`（现有） | 列表页曝光 / 点击 | 新增 `cover_is_ai` |
| `after_sale_ticket_create`（现有） | 发起售后 | 新增 `cover_is_ai`、纠纷原因 |

**实验设计**

- **分流单位**：卖家。实验组看得到入口，对照组看不到；方差按卖家聚类计算。
- **比较口径**：按分组意向（ITT）比较。实验组内“用了 vs 没用”存在自选择偏差，只作参考。
- **时长**：至少 4 周，覆盖 14 日成交窗口和两个完整自然周；样本量在拿到基线后计算。
- **溢出风险**：两组商品在同一信息流里竞争，实验组可能“抢走”对照组的点击，高估提升。用按城市或类目切分的对照做稳健性检验。
- **护栏判定**：货不对板纠纷率显著上升即暂停放量，不论点击率如何。

## 11. 风险与待决问题

最大的风险是主图好看了、纠纷也多了；第 7 节的硬约束和第 9 节的护栏都是为它设的。

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 卖家借 AI 主图掩盖瑕疵 | 货不对板纠纷上升，买家信任下降 | 主体不重绘 + 原图强制保留 + 纠纷率护栏 |
| 难例抠图失败（透明、反光、毛绒、细线类商品） | 主图反而变差，卖家不再使用 | 评测集覆盖难例；边缘质量低于阈值即降级；按类目白名单逐步放开 |
| 白底图千篇一律，个人卖家看起来像商家 | 信息流辨识度下降，部分买家更不信任 | 提供浅场景背景（F6）；实验中按背景类型拆分点击率 |
| 换背景绕过盗图检测 | 盗图商品更难发现 | 对源原图做跨商品重复检测 |
| 推理成本超预期 | 无法全量免费开放 | 免费额度 + 限流；同一输入图结果缓存 |
| 依赖第三方模型服务 | 可用性与照片数据流向不受控 | 供应商评估含数据条款；服务不可用时按 F14 降级 |

**待决问题**

- [ ] 上线地区适用哪些 AI 生成内容标识或虚假宣传法规，显式和隐式标识各自的具体要求是什么？（法务）
- [ ] 自研模型还是第三方 API？这决定成本、时延和照片是否出境。（技术）
- [ ] 是否收费：免费额度多少，高频卖家能否付费加量？（产品 / 商业）
- [ ] AI 主图引发的纠纷，判责规则是否与普通纠纷一致？（平台规则 / 客服）
- [ ] 首期开放的通用实物类目白名单有哪些？二手车类目是否在本期开放？（产品 / 算法）
- [ ] 评测集从哪里来、许可如何？真实上传需用户授权，且不得提交到代码仓库。（数据）
- [ ] 当前主图点击率、14 日成交率、货不对板纠纷率的基线各是多少？（数据）
